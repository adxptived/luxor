## 2. Что уже сделано (коммит в ветке)

### 2.1 Сохранение терминалов между перезапусками

Новый модуль `src/lib/terminalState.ts`, интеграция в `src/panels/TerminalPanel.tsx`.

- Сохраняются: вывод с цветами (`@xterm/addon-serialize`), несохранённая строка
  ввода, текущая папка (только если шелл шлёт OSC 7).
- Восстановление: вывод пишется под пометкой «восстановлено из прошлой сессии»,
  шелл стартует заново, строка ввода набирается обратно **без** Enter.
- Сохранение: троттлинг ~2,5 с + принудительный flush на `pagehide` /
  `visibilitychange→hidden`.
- Хранилище: `localStorage["luxor.term.<dockKey>:<panelId>"]`, бюджет 150 КБ на
  терминал и ~1,5 МБ всего (вытеснение старых).
- Ключ включает проект (`DockKeyContext`): пресеты layout сохраняют id панелей,
  и без этого два терминала из одного пресета делили бы снимок.
- Закрытие вкладки удаляет снимок (`onDidRemovePanel`); сироты чистятся при
  старте (`pruneTerminalStates`, grace 60 с).
- Настройка: Settings → Terminal → «Restore terminals on startup» (выкл. = стереть всё).
- **Пароли:** нажатия на запросах без эха (`Password:`, `[sudo] password for …:`,
  passphrase, `Пароль:`) не попадают ни в снимок, ни в историю команд. Это
  заодно закрыло существовавшую утечку: `cmdHistory` писал в localStorage всё,
  что вводили вслепую.
- Тесты: `src/lib/terminalState.test.ts` (14), `e2e/terminal-restore.spec.ts` (2).

Известные ограничения: папка восстанавливается не у всех шеллов (PowerShell не
шлёт OSC 7) — надёжное решение в §5 (P5).

## 3. Найденные недоработки (не исправлено)

### 3.1 Первый запуск и онбординг

- **Две системы онбординга, один ключ.** Тур (`OnboardingTour`, `lib/onboarding.ts`)
  и чеклист «Get started» на Welcome (`WelcomePanel.tsx:74,89`) пишут в
  `localStorage["luxor.onboarding"]` в разных форматах; тур затирает прогресс чеклиста.
  На первом экране пользователь видит оба сразу.
- **Хоткеи захардкожены**: `Ctrl+\`` на Welcome, `Ctrl+O` / `Ctrl+Shift+G` в
  тексте тура, `Ctrl+Shift+P` в подсказке — игнорируют ремап и macOS, хотя
  `hintFor()` / `formatChord()` (`lib/hotkeys.ts`) уже есть.
- Welcome: мёртвое место внизу левого блока; подсказка про палитру дублирует
  плашку «Command-first».

### 3.2 Верстка

- **Вкладки проектов в верхней панели обрезаются** при ≥3 вкладках: первая
  обрезана слева («lank workspace»), последняя вылезает за край полосы. На 900/700 px
  полоса получает ~250 px при ~600 свободных. Это единственный стабильно красный
  e2e: `e2e/chrome-layout.spec.ts:19`. Возможна поправка на шрифт (см. §1).

### 3.3 Локализация

- ≈290 из ≈1075 строк `t()` (≈27%, оценка скриптом) без русского перевода:
  командная палитра («Commands», «Recently used», «No matching commands»),
  переключатель проектов, виджеты правой панели, `NoFolderCta`, «Move to sidebar»,
  блок About, пресеты настроек. Теста на покрытие нет.
- Подсказки на Welcome — английские строки-ключи, переводятся только если есть в словаре.

### 3.4 Обратная связь и ошибки

- ~68 мест `.catch(() => {})`. В пользовательских действиях это «нажал — ничего»:
  `TopBar.tsx:735` (Open in file manager), `ptyWrite` / `ptyResize`, назад/вперёд/
  reload во встроенном браузере (`BrowserPanel.tsx`).
- **Обновления фактически выключены:** `ui.update_repo` по умолчанию пустой
  (`config.rs:301`), и при пустом значении проверка при старте не запускается.
  Автоапдейтера нет. Даже когда проверка включена, результат — исчезающий toast
  без ссылки на релиз (`App.tsx` ~410).
- `PanelErrorBoundary` написан, но **нигде не подключён** — падение панели не
  изолируется (общий `AppErrorBoundary` в `App.tsx` есть).

### 3.5 Потеря данных и диалоги

- Защита от несохранённых правок (`lib/dirtyGuard.ts`) работает только при
  закрытии вкладки (`dockStore.ts:405`). При выходе из приложения (`lib.rs`
  `WindowEvent::Destroyed`, Quit из трея, `close_to_tray=false`) все PTY
  убиваются без вопроса — ни про несохранённые файлы, ни про живые процессы.
- `window.confirm` вместо собственного диалога (`useUiStore.confirm`):
  конфликт записи — `EditorPanel.tsx:423`; autorun из пресета — `autorunGuard.ts:38`
  (текст без перевода).

### 3.6 Тесты

- Красные и **до** моих правок: `chrome-layout.spec.ts:19` (§3.2) и
  `popups.spec.ts:6` («settings closes on Esc and on outside click», падает на
  чистом `HEAD` при `--workers=1`).
- `popups.spec.ts:23` (палитра) упал в одном из двух прогонов, остальные зелёные —
  вероятно, нестабильный тест.

### 3.7 Rust

- `discord::tests::set_activity_sends_wellformed_frames_over_mock_ipc`
  (`discord.rs:1622`) не завершился за 60 с в песочнице. Тест кладёт mock-пару
  `UnixStream` и ставит read-timeout только серверной стороне; возможно, клиентская
  сторона ждёт ответа Discord. **Не подтверждено** — проверить локально/в CI.
- `crates/luxor-core/src/config.rs`: комментарий «Monaco color theme» устарел.

## 6. Рекомендуемый порядок исполнения

`P1 (U1–U7)` → `P3 (R1–R3)` → `P2 (U8–U11)` → `P3 (R4–R6)` → `P4` → `P5`.

Почему так: P1 даёт самый заметный пользовательский эффект и позеленит тесты;
безопасные удаления уменьшают поверхность до остальной работы; R4–R6 затрагивают
Rust/Tauri и требуют сборки, их удобнее делать с рабочим CI-циклом; документацию
пишем после удаления, чтобы не переписывать дважды.
