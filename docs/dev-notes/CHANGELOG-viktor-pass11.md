## Что сделано в этом проходе (pass 11)

### #30 — Граф коммитов (ветки/мержи), бэкенд + тесты ✅

Это единственный пункт из «топ-10 по польза/усилие», у которого реально
отсутствовал бэкенд (а `log` уже отдаёт `parents` «for graph rendering», но без
раскладки по дорожкам). Добавил чистую, детерминированную функцию раскладки —
её можно гонять и на сервере, и на клиенте, и она полностью покрыта unit-тестами.

`crates/luxor-core/src/gitx.rs`:
- `pub struct GraphRow { id, column, parent_columns, width }` (`Serialize`).
- `pub fn commit_graph(commits: &[CommitInfo]) -> Vec<GraphRow>` — алгоритм
  назначения дорожек (lanes): для каждого коммита находим ожидающую его дорожку
  (или выделяем новую для «кончика» ветки), схлопываем дубли-дорожки от мержа,
  первый родитель идёт по той же колонке, остальные — в переиспользуемые/новые
  дорожки; хвостовые свободные дорожки подрезаются.
- 3 теста: `graph_empty_is_empty`, `graph_linear_history_stays_in_one_lane`,
  `graph_branch_and_merge_uses_two_lanes`.

Осталось (требует локальной сборки Tauri): SVG/canvas-рендер графа в `GitPanel`
и вызов команды. Бэкенд готов и отдаёт ровно те колонки/ширину, что нужны UI.

## Что НЕ сделано и почему (нужна твоя локальная сборка)

1. **GUI-обвязка** большинства уже-готовых бэкендов (граф коммитов, blame-вью,
   stash-меню, 3-way merge editor, редактор строк БД, SQL-консоль, hex-вью,
   мультивыбор в проводнике, редактор хоткеев, импорт VS Code-тем и т.д.) —
   код команд/панелей можно написать, но проверить только сборкой на твоей
   машине с webkit/gtk.
2. **Отсутствующие бэкенд-куски:** file-watcher (notify), корзина (trash),
   `push --force-with-lease`, интерактивный rebase/squash, постадийный stage по
   ханкам (`add -p`), GPG/SSH-подпись коммитов, asciinema-запись, Postgres/MySQL
   в БД-вьюере, proptest/criterion, плагин-API (#100). Часть из них (force-push,
   rebase, PR-merge) требует сети/реального remote и не проверяется юнит-тестами —
   шипить непроверенным не стал, чтобы не давать ложную уверенность.
