## Исправленные баги

### 0. Сборка ядра падала на stable (E0597) — `fsx.rs`
`stmt.query_map(...).collect()` стоял хвостовым выражением блока → временный
`MappedRows` жил дольше `stmt`. Привязал к `let rows = ...; rows` в обоих
местах (колонки и индексы). Теперь компилируется.

### 1. Паника поиска на не-ASCII при регистронезависимом литерале — `search.rs`
Старый код искал в `content.to_lowercase()`, а смещения применял к исходной
строке. `to_lowercase()` меняет длину в байтах (`İ`, `ß`, …) → смещение
уезжало в середину UTF-8 символа → паника при срезе. Переписал матчер: CI-литерал
компилируется в экранированный регистронезависимый `regex`, смещения всегда на
границах символов. Тест: `ci_literal_replace_handles_non_ascii_without_panicking`.

### 2. `read_text` грузил весь файл в память
Открытие много-гигабайтного лога читало файл целиком, чтобы отбросить почти
всё. Теперь читаем окно ≤ `max_bytes` (`read_head` через `File::take`), пик
памяти ограничен. Обрезка хвоста — по `from_utf8().valid_up_to()` (не рвём символ).

### 3. Один битый enum в конфиге сбрасывал ВЕСЬ конфиг — `config.rs`
Неизвестное значение enum (тема из новой версии и т.п.) ломало парс целиком, и
`load_or_recover` сбрасывал все настройки в дефолт. Добавил
`de_enum_lenient`: незнакомое значение откатывается к дефолту **поля**, остальные
настройки целы. Поля: `quick_actions`, `diff_view`, `cursor_style`, `theme`,
`tab_bar_position`. Тест: `unknown_enum_value_falls_back_to_default_not_reset`.

### 4–5. Запись файла теряла права и подменяла симлинки — `fsx.rs`
Запись через temp+rename создавала новый файл с правами по umask (терялся бит
`+x` у скриптов) и заменяла симлинк обычным файлом. Новый `atomic_write`:
сохраняет права назначения, пишет «сквозь» симлинк в его цель, уникальное имя
temp (UUID) → нет гонки двух сохранений, чистит temp при ошибке rename. Тесты:
`write_text_preserves_unix_permissions`, `write_text_follows_symlink_to_target`.

### 6 + 12. Поиск и замена расходились + кривые номера строк — `search.rs`
Поиск шёл построчно, замена — по всему файлу (regex), мультистрочные паттерны
вели себя по-разному, смещения колонок плыли. Теперь и поиск, и замена работают
по всему содержимому, а смещения маппятся в строку/колонку через таблицу начал
строк. Тесты: `search_reports_correct_line_numbers_whole_file`,
`multiline_regex_preview_and_replace_agree`.

### 7. Бесконечная рекурсия на цикле симлинков — `search.rs`
Старый обход шёл по `path.is_dir()` и ходил по симлинк-директориям → цикл →
переполнение стека. Перешёл на walker из крейта `ignore` с `follow_links(false)`.
Тест: `symlink_cycle_does_not_recurse_forever`.

### 8. `http_request` буферизовал тело целиком — `httpx.rs`
`resp.bytes()` тянул весь ответ в память до обрезки. Теперь стримим по чанкам и
останавливаемся на лимите `MAX_BODY_BYTES`.

### 9. OSV: severity и summary всегда пустые — `httpx.rs`
`querybatch` возвращает только ID уязвимостей (без summary/severity), а код читал
их прямо оттуда → всегда пусто. Теперь после batch добираем детали каждой
уязвимости `GET /v1/vulns/{id}` и заполняем summary + severity (`osv_severity`:
label из `database_specific` или CVSS-вектор). Тест: `osv_severity_extraction`.

### 10. Паника при старте, если не собрался HTTP-клиент — `ai.rs`
`.expect("reqwest client")` → `.unwrap_or_else(|_| reqwest::Client::new())`, чтобы
приложение всё равно стартовало.

### 11. Литеральная замена ломала `$1` и т.п.
CI-литеральная замена шла через regex и интерпретировала `$1`/`${name}` как
группы. Теперь вербатим через `regex::NoExpand`. Тест:
`literal_replacement_text_is_verbatim_even_with_dollar`.

## Добавленные улучшения

- **Поиск уважает `.gitignore`** (внутри git-репо) — артефакты сборки,
  `node_modules` и т.п. не засоряют результаты; тяжёлые/VCS-папки из `SKIP_DIRS`
  всё равно жёстко пропускаются даже без `.gitignore`. Крейт `ignore = "0.4"`.
  Тест: `respects_gitignore_inside_a_repo`.
- **Защита от порчи данных при замене**: файлы не в валидном UTF-8 пропускаются
  (не пишем обратно «lossy»-версию). `readable_text_strict`.
- **Атомарная запать с сохранением прав/симлинков** теперь и в
  `write_text_encoded` (раньше — обычный `fs::write`).

## Сознательно НЕ менял / отложено (с обоснованием)

- **`shellQuote.ts` (двойные кавычки)** — оставил как есть. Это намеренный
  кросс-платформенный компромисс (Windows-пути `C:\…`), тесты его фиксируют, а
  путь только **вставляется** в терминал, не выполняется. Перевод на POSIX
  одинарные кавычки сломал бы Windows — это был бы регресс, а не фикс.
- **Жёсткий path-sandbox для `fsx`** — отложено: сломает файловый проводник,
  который **по дизайну** свободно ходит по ФС. Нужна продуктовая настройка
  разрешённых корней, иначе сломаем UX.
- **git `--force-with-lease` / пуш в другую ветку**, **виртуализация больших
  файлов в редакторе (Monaco)** — это сквозные изменения во фронтенде + Tauri
  (`src-tauri`), а его **нельзя собрать в песочнице** (нужны системные webkit/gtk).
  Ключевую защиту памяти для больших файлов в ядре (`read_text`) уже сделал.
  Готов сделать эти три пункта отдельным проходом, если нужно.
