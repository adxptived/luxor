# Luxor — Viktor pass38

Фокус: вкладка редактора (editor tab) + старт приложения.

## 1. Тулбар редактора → одно меню «⋯» с хоткеями
Раньше: ряд кнопок с рамками (Save / Find / Replace / Commands) + селекторы языка / темы / размера шрифта.
Теперь тулбар минимальный и без рамок:
- слева — имя файла и путь;
- метка языка (например, `Shell`) — только индикатор;
- кнопка предпросмотра (для `.md` / `.html`);
- одна кнопка **«⋯»** — открывает меню со всеми действиями и их хоткеями:
  - Save `Ctrl+S`, Find `Ctrl+F`, Replace `Ctrl+H`, Format document `⇧⌥F`,
    Command palette `F1`, Go to line `Ctrl+G`
  - Word wrap `Alt+Z`, Show whitespace, Increase / Decrease font size
  - **Syntax: …** (выбор языка — вложенный список), **Editor theme: …** (выбор темы)
  - Keyboard shortcuts
- Файлы: `src/panels/EditorPanel.tsx`, `src/components/Overlays.tsx`
  (в контекстное меню добавлен скролл `max-h + overflow-y-auto`, чтобы длинный
  список языков не выходил за экран).

## 2. Убраны «белые обводки по краям»
- В тулбаре редактора удалены все `border` у кнопок и селекторов — теперь
  подсветка только фоном при наведении (как в остальном UI).
- Шапка встроенного редактора в проводнике (`FilesPanel.tsx`): кнопки
  «открыть в IDE / в отдельной вкладке / закрыть» стали безрамочными;
  нижняя граница смягчена (`border-edge/50`).

## 3. Подсветка синтаксиса
Раньше файлы без расширения (git-хуки, скрипты) открывались как Plain Text.
- `src/lib/editorLanguage.ts`:
  - распознавание имён git-хуков (`commit-msg`, `pre-commit`, …) и их
    `.sample`-вариантов → **shell**;
  - детект по **shebang** (`#!/usr/bin/env python3` → python, `#!/bin/sh` → shell
    и т.д.) — новая функция `detectLanguage(path, content)`;
  - добавлены расширения: `bat/cmd, lua, dart, scala, pl/pm, r, gradle/groovy,
    proto, graphql, hcl/tf, diff/patch`, имена `.gitattributes, .bashrc, .zshrc,
    .profile` и т.п.
- `EditorPanel.tsx` теперь определяет язык уже **после** чтения файла, с
  fallback на shebang — поэтому `commit-msg.sample` подсвечивается как Shell
  (см. скриншот).

## 4. Производительность / старт
Фронтенд-путь старта уже хорошо оптимизирован (мгновенный inline-сплэш в
`index.html`, ленивый Monaco на idle, отложенные gateway/пресеты, показ окна по
первому кадру). Стартовый JS-бандл ≈ 1.5 МБ (Monaco 3.9 МБ грузится лениво,
не в стартовом графе). Панели импортируются **eager-ом намеренно** — динамический
`import()` в Tauri webview даёт «пустые вкладки» (это в коде помечено, не трогаю).

Вывод: 10 c — это почти наверняка **нативная** часть, а не фронтенд. Наиболее
вероятные причины (по убыванию):
1. **debug-сборка** (`cargo tauri dev` / без `--release`) стартует в разы дольше
   релизной — проверь, что меряешь именно release-бандл.
2. **Windows Defender / антивирус** сканирует неподписанный `.exe` при запуске
   (на dev-сборках частая причина +несколько секунд).
3. **WebView2 cold start** (первый запуск после загрузки ОС).

Безопасная правка (review-only, нужен ребилд): в `src-tauri/src/lib.rs` снизил
failsafe-показ окна `800 → 450 мс` — фон окна `#101014` совпадает со сплэшем,
белой вспышки не будет, окно появляется раньше.

Чтобы я точно нашёл причину — скинь строку `STARTUP firstPaint=… htmlLoaded=…
jsReady=…` из frontend.log и подтверди: это release или dev-сборка?
