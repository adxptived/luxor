## 0. Резюме

Проект в **хорошем инженерном состоянии**: строгий TS без `any`, PathGuard на всех мутирующих
FS/DB-командах, секреты только в OS keychain, git через libgit2 (без shell), санитайз markdown
через DOMPurify, встроенный браузер как child webview без capabilities, грамотный code-splitting
(xterm / codemirror по языкам / dockview / i18n отдельными чанками), 68 дизайн-токенов, 16 тем,
39 keyframes, реестр localStorage-ключей с тестом-сторожем, focus-trap и aria-live в оверлеях.
P0-дыры предыдущего аудита (2026-07-03) действительно закрыты.

Но найдено одно **системное упущение, которое объясняет почти все дефекты ниже**:

> ### CI никогда не запускался
> Workflow-файлы лежат в `ci/workflows/`, а каталога `.github/workflows/` в репозитории
> **нет вообще**. `ci/workflows/README.md` честно пишет, что их вынесли из-за отсутствия
> `workflow`-scope у Git-интеграции — и назад не вернули. В результате на `main` спокойно
> живут 3 ошибки clippy и 4 падающих теста, хотя `ci.yml` их поймал бы: там прописан
> `-D warnings` и матрица ubuntu/windows/macos.

Всё остальное делится на: **6 реальных багов** (один — P0, убивает процессы пользователя),
**4 красных гейта**, **перф-резервы** и **UI/UX-долг** (нет типографической шкалы,
reduced-motion работает по ручному allowlist, нет exit-анимаций).

## 1. Красные гейты (починить первым делом)

### 1.1 [P0] CI не существует

`.github/workflows/` отсутствует; `ci/workflows/{ci,release,visual-regression}.yml` — «припаркованы».

**Фикс:** перенести 3 файла в `.github/workflows/`. Требуется push с `workflow`-scope
(вручную через web UI GitHub или локальный клон с полными правами) — агентная Git-интеграция
это сделать не сможет, поэтому шаг ручной и должен быть выполнен владельцем репозитория.

Побочный баг в `visual-regression.yml` (строки 20–33): Vite стартует в одном step
(`bunx vite &`), а используется в следующем. GitHub Actions завершает фоновые процессы
шага вместе с его shell — job держится только на удаче. Плюс `exit 0` внутри retry-цикла
завершает step успешно, но сервер при этом уже мёртв.
**Фикс:** запускать Vite через `playwright.config.ts` `webServer` (он там уже настроен на порт
4173), либо объединить старт и использование в один step.

### 1.2 [P1] 3 ошибки clippy

| Файл | Лишай | Фикс |
|---|---|---|
| `crates/luxor-core/src/pty.rs:470` | `unused_imports`: `std::time::Duration` | удалить строку |
| `crates/luxor-core/src/discord.rs:424` | `needless_update`: `..Default::default()` при всех заданных полях | удалить `..Default::default()` |
| `crates/luxor-core/src/telemetry.rs:61` | `should_implement_trait`: свой `from_str` | переименовать в `parse` (или реализовать `std::str::FromStr`) |

`from_str` вызывается из нескольких мест — переименование потребует правки вызовов;
`impl FromStr` предпочтительнее, но тогда возврат станет `Result`, а сейчас функция
инфаллибельна (неизвестное значение → дефолт). Проще и честнее: `Category::parse(&str) -> Category`.

### 1.3 [P1] 2 теста gitx падают на Windows из-за CRLF

```
gitx::tests::stash_save_list_apply_pop_drop  left: "dirty\r\n"  right: "dirty\n"
gitx::tests::unstage_and_discard             left: "v1\r\n"     right: "v1\n"
```

Причина: тесты создают временный репозиторий, но **наследуют глобальный
`core.autocrlf=true`** — это дефолт Git for Windows. `discard()` делает checkout, git
разворачивает LF→CRLF, а тест ждёт `"v1\n"`.

Это не «мелочь на моей машине»: так упадёт у любого Windows-контрибьютора с дефолтным
git-конфигом. Тест не герметичен.

**Фикс** — в `temp_repo()` (`crates/luxor-core/src/gitx.rs`) явно выключать преобразование
для тестового репо:

```rust
// Тесты должны быть герметичны: глобальный core.autocrlf=true (дефолт Git for
// Windows) иначе разворачивает LF→CRLF на checkout и ломает сравнения содержимого.
let mut cfg = repo.config().unwrap();
cfg.set_bool("core.autocrlf", false).unwrap();
```

### 1.4 [P1] Тест discord дёргает реальный сокет Discord

`discord::tests::reconnect_backoff_throttles_missing_discord` (`discord.rs:1578`) называется
«missing_discord», но ничего не мокает: он зовёт `ipc.connect(now)`, внутри которого
`IpcStream::connect()` перебирает реальные пути named pipe / unix-сокета. Если Discord
на машине **запущен**, connect успешен → `next_connect_at` остаётся `None` → падает
`assert!(next.is_some())`.

**Фикс:** вынести обнаружение сокета за интерфейс, который тест может подменить
(например поле-фабрика `connector: fn() -> Option<IpcStream>` в `DiscordIpc`), и в тесте
передавать заглушку, возвращающую `None`. Тогда тест реально проверяет backoff, а не
наличие Discord у разработчика.

### 1.5 [P2] Тест `formatRange` зависит от локали ОС

```
src/lib/dbHelpers.test.ts:39
Expected: "1–200 of 1,024"   Received: "1–200 of 1 024"
```

`dbHelpers.ts:33` использует `toLocaleString()` без локали → на ru-RU машине разделитель
разрядов — узкий пробел. На GitHub-раннерах (en-US) тест зелёный, локально красный.
Это симптом более широкой проблемы — см. **2.3**.

## 2. Реальные баги

### 2.1 [P0] Смена языка интерфейса убивает все терминалы

`src/App.tsx:649`:

```tsx
<div key={getLanguage()} className="flex h-screen w-screen flex-col …">
```

`key` на корневом узле → при смене языка React **размонтирует всё дерево**. В cleanup
`TerminalPanel` (`src/panels/TerminalPanel.tsx:467`):

```ts
if (sessionId) void ipc.ptyKill(sessionId).catch(() => {});
term.dispose();
```

А `src/lib/terminalSession.ts:6` прямо документирует: «The actual PTY process is not
persisted». Итого: **пользователь переключает English → Русский и теряет все запущенные
процессы** — `cargo watch`, `bun run dev`, незакоммиченные сессии. Вместе с ними уезжают
layout dockview, история undo в редакторах и позиции скролла.

При этом `key` **уже избыточен**: в `App.tsx:397` есть

```ts
useSyncExternalStore(subscribeLanguage, getLanguageVersion, getLanguageVersion);
```

то есть App и так перерисовывается на смену языка, а дети почти все не мемоизированы
(во всём проекте лишь 7 `memo`) — значит `t()` в них переоценивается и без remount.

**Фикс:** убрать `key={getLanguage()}`. Для мемоизированных компонентов (их мало, и они
появятся при работе над 3.2) ввести хук `useT()`, подписанный на тот же
`subscribeLanguage`, чтобы они не «залипали» на старом языке:

```ts
// src/lib/i18n.ts
export function useT(): typeof t {
  useSyncExternalStore(subscribeLanguage, getLanguageVersion, getLanguageVersion);
  return t;
}
```

Регрессионный тест (Playwright, e2e): открыть терминал, сменить язык в настройках,
убедиться что `pty` жив и вывод на месте.

### 2.2 [P1] Побочный эффект в теле рендера

`src/App.tsx:398`: `void setLanguage(language);` — вызов, меняющий модульное состояние
и способный дёрнуть `notify()`, стоит прямо в теле компонента. Под `React.StrictMode`
(включён в `src/main.tsx:71`) рендер в dev вызывается дважды; в concurrent-режиме рендер
может быть отброшен. Сейчас спасает только guard `if (changed) notify()`.

**Фикс:** перенести в `useEffect([language])`.

### 2.3 [P1] Числа и даты форматируются по локали ОС, а не по языку приложения

В `src/lib/i18n.ts:54` уже есть ровно для этого написанный `getLocale()` с подробным
комментарием («Without this, `toLocaleDateString` falls back to the system locale…»).
Но он используется в **12** местах, а **16 call sites его игнорируют**:

```
src/components/HexView.tsx:87          src/panels/GitExtras.tsx:101
src/components/StatusBar.tsx:419,421   src/panels/GitPanel.tsx:447,544,673
src/lib/dbHelpers.ts:33                src/panels/HtmlPreviewPanel.tsx:334
src/panels/DbPanel.tsx:136,593         src/panels/HttpPanel.tsx:319

src/panels/EditorPanel.tsx:994
```

Следствие: русский UI на английской ОС показывает `7/26/2026`, английский UI на русской —
`1 024` вместо `1,024`. И именно это роняет тест 1.5.

**Фикс:** централизовать в `src/lib/format.ts` — `formatNumber()`, `formatDateTime()`,
`formatTime()`, `formatBytes()`, все через `getLocale()`. Заменить 16 мест. Добавить
ESLint-правило `no-restricted-syntax`, запрещающее `toLocaleString`/`toLocaleDateString`/
`toLocaleTimeString` вне `format.ts` — иначе долг вернётся.

### 2.4 [P2] `fs_write_text_encoded` теряет защиту от конфликта записи

`src-tauri/src/commands/fsx.rs`: `fs_write_text` принимает `expected_mtime_ms` и через

сделанные снаружи.

**Фикс:** добавить `expected_mtime_ms: Option<i64>` и `write_text_encoded_checked` по образцу
`write_text_checked`.

### 2.5 [P2] Мёртвый код в HtmlPreviewPanel

`src/panels/HtmlPreviewPanel.tsx:53` — `resolvePreviewSrc()` после сужения

идёт по else-ветке, что как раз правильно, но читается как баг.

**Фикс:** удалить `resolvePreviewSrc`, `previewSrc`, недостижимый iframe и упростить
`doRefresh` до одной ветки. Комментарий про безопасность сохранить над оставшимся
`srcDoc`-iframe.

## 3. Производительность

### 3.1 [P2] DbPanel рендерит строки без мемоизации

**Поправка к первой редакции этого документа.** Изначально здесь стояло P1 с оценкой
«до 10 000 строк». Это неверно: 10 000 — лишь потолок клампа на бэкенде
(`crates/luxor-core/src/fsx.rs:870`), а фронт столько никогда не запрашивает.
Реальные объёмы ограничены:

- таблица (`src/panels/DbPanel.tsx:435`) пагинирована, `PAGE_SIZES = [50,100,200,500]`,
  по умолчанию 200;
- SQL-результат (`src/panels/DbPanel.tsx:950`) идёт через `ipc.dbQuery(...)` с
  `maxRows = 500` по умолчанию (`src/lib/ipc.ts:606`).

Так что «десятков тысяч узлов в кадре» не бывает — максимум ~500 строк.

Тем не менее проблема есть, только другая: **каждая строка — не мемоизированный inline-JSX
с обработчиками на каждой ячейке**. Любое изменение состояния панели (начало
редактирования ячейки, открытие detail-попапа, смена сортировки) перерисовывает все
500 строк со всеми ячейками.

**Фикс:** вынести строку в `memo`-компонент со стабильными коллбэками — это снимает
основную стоимость и не требует ломать семантику `<table>`. Полная виртуализация
через `Virtualizer as="tbody" item="tr"` возможна, но абсолютное позиционирование строк
внутри таблицы конфликтует с табличным layout — при ≤500 строках овчинка выделки не стоит.

### 3.2 [P1] Почти нет мемоизации

7 `memo` на 45k LOC. `src/App.tsx:104` сам это документирует:

> «Previously `useAppStore((s) => s.config)` re-rendered App (and its un-memoized
> TopBar/RightPanel/StatusBar/DockLayout subtree) on every settings save»

Селекторы починили, но сами компоненты так и остались немемоизированными — любой ререндер
App (а он подписан на 5 сторов) прокатывается по всему шеллу.

**Фикс:** `memo` на `TopBar`, `NavRail`, `SidePanel`, `RightPanel`, `StatusBar`,
`QuickActions`, `WindowChrome`; замерить до/после через существующий
`src/perf/perfMeasure.ts` и `bench:editor`.

### 3.3 [P2] Обработчик горячих клавиш на каждое нажатие

`src/App.tsx:449–557`: на **каждый** keydown (включая набор текста в редакторе и терминале)
идёт цепочка до ~15 последовательных `matchChord(e, keys[...])`, каждый — разбор строки.
`effectiveHotkeys` мемоизирован (`src/lib/hotkeys.ts:70`) — это уже хорошо, но сам
`matchChord` вызывается многократно.

**Фикс:** один раз построить `Map<normalizedChord, actionId>` (там же, где кешируется
`effectiveHotkeys`), в обработчике нормализовать событие в строку и сделать одну

### 3.4 [P2] 4 отдельных effect'а под tray-события

`src/App.tsx:321, 353, 372` (+ `cli:open` в 275) — каждый со своим `ipc.listen`,

**Фикс:** один effect с таблицей `{ event → handler }`, или маленький хук

### 3.5 [P2] CSS-бандл 159 kB

`dist/assets/main-*.css` = 159 192 B несжатых при 2536 строках своего CSS + Tailwind.

## 4. Безопасность (упрочнение; открытых дыр не найдено)

Прошлый P0 (FS-команды без project root) закрыт: `src-tauri/src/pathguard.rs` +
16 вызовов `ensure_within_projects` (12 в `fsx.rs`, 2 в `launcher.rs`, по 1 в `extras.rs`
и `pty.rs`), канонизация симлинков, read-only команды осознанно
не ограничены (нужно ходить по диску, чтобы открыть новый проект). `db_query` при
`allow_write=false` открывает **read-only соединение** (`fsx.rs:847`) — то есть
allowlist по первому слову не единственная защита, а второй слой. Это правильно.

### 4.1 [P2] `opener:allow-open-path` с `**`

`src-tauri/capabilities/default.json`:

```json
{ "identifier": "opener:allow-open-path", "allow": [{ "path": "**" }, { "path": "**/" }] }
```

Любой путь можно открыть штатным приложением ОС.

**Решение по итогам работы: оставить `**`, задокументировав как осознанный выбор.**
Сузить не получится по существу: capability-скоупы в Tauri **статичны** и вычисляются
на этапе сборки, а «текущие project roots» существуют только в рантайме. Фиксированный
список сломал бы основной сценарий — открыть любой файл, который пользователь сам выбрал
в проводнике. Для dev-инструмента это его прямая работа.

Остающийся риск (XSS/вредоносный плагин просит ОС открыть произвольный путь) закрыт там,
где он реально опасен: путь уходит в системный API ассоциаций, а не в шелл — см. 4.2.
Обоснование записано прямо в `src-tauri/capabilities/default.json`, чтобы следующий
аудит не «чинил» это повторно.

### 4.2 [P2] `cmd /C start` и метасимволы в имени файла

`crates/luxor-core/src/launcher.rs:236`:

```rust
program: "cmd".into(),
args: vec!["/C".into(), "start".into(), String::new(), path.into()],
```

Аргументы передаются массивом (не строкой), инъекции через пробелы нет. Но `cmd.exe`
**парсит свою командную строку по своим правилам**, отличным от экранирования, которое
делает Rust `Command` — метасимволы `&`, `|`, `^` в имени файла исторически являются
вектором (ср. CVE-2024-24576). Файл с именем `a&calc.txt` может прийти из склонированного
репозитория.

**Сделано, в два уровня:**
- `src-tauri/src/commands/launcher.rs` — команды идут через `tauri_plugin_opener::open_path`
  (плагин уже был в зависимостях и зарегистрирован), то есть через `ShellExecuteW`;
- `crates/luxor-core/src/launcher.rs` — крейт не может зависеть от Tauri, поэтому там
  `cmd /C start "" <path>` заменён на `explorer.exe <path>`: та же ассоциация по умолчанию,
  но без шелла-посредника.

Оставшиеся два `cmd /c start` (строки ~282 и ~675) запускают **терминалы**, а не файлы:
аргумент приходит из фиксированного списка (`cmd`/`powershell`/`pwsh`) или из настроек,
которые пользователь задаёт себе сам. Содержимое репозитория туда не попадает, поэтому
вектор из CVE-2024-24576 к ним неприменим.

## 5. UI/UX и анимации

Фундамент сильный: 68 CSS-переменных, 16 тем (включая 4 светлые), семантические цвета
(`success/warning/danger/info` + `*-soft` варианты), шкала радиусов, **motion-токены**
(`--lx-ease`, `--lx-ease-spring`, `--lx-dur-fast/dur/dur-slow`), палитра для графиков,
вычисляемый в рантайме `--lx-on-accent` под контраст. 39 keyframes, кроссфейд тем,
focus-trap в оверлеях, aria-live. Это уже выше среднего.

Улучшать нужно не основы, а **глубину и консистентность**.

### 5.1 [P1] В типографической шкале нет ступеней ниже 12px — 184 обхода токенов

Шкала Tailwind используется и используется активно: `text-xs` — 447 раз, `text-sm` — 133,
`text-base` — 8, `text-lg` — 6. То есть де-факто ритм есть.

Проблема в другом: самая нижняя ступень Tailwind — `text-xs` = 12px, а UI Luxor'а плотный
и ему постоянно нужно 10–11px. Токена для этого нет, поэтому размер хардкодят в брекетах:

```
96 × text-[10px]      75 × text-[11px]      8 × text-[9px]
 4 × text-[13px]       1 × text-[12px]      ← и он же равен text-xs
```

Следствия: (а) 184 места живут вне шкалы и разъезжаются; (б) `text-[12px]` дублирует
`text-xs`, а `text-[13px]` — дырка между `xs` и `sm`; (в) `px` не масштабируются
пропорционально при зуме приложения (`ZOOM_STEP`, `core:webview:allow-set-webview-zoom`);
(г) **9px нечитаемы** — 8 мест надо просто поднять.

**Фикс:** дополнить шкалу снизу двумя ступенями в `@theme` и перевести 184 места на них:

```css
--text-3xs: 0.625rem;   /* 10px — бейджи, метки статус-бара (96 мест) */
--text-2xs: 0.6875rem;  /* 11px — вторичный текст панелей (75 мест) */
```

`rem` вместо `px` даёт корректное масштабирование. `text-[9px]` → `--text-3xs`,
`text-[12px]` → `text-xs`, `text-[13px]` → `text-sm`.

### 5.2 [P1] reduced-motion работает по ручному allowlist и уже протекает

`src/styles.css:2401` — блок `@media (prefers-reduced-motion: reduce)` перечисляет
**~45 классов вручную**. Плюс два более ранних блока (976, 984). Любая новая анимация
молча выпадает из защиты — и это уже произошло: Tailwind-утилиты `animate-pulse`
(6 × `DevToolsPanel`, `EditorPanel`, `HtmlPreviewPanel`) и `animate-spin` (23 места)
в списке **отсутствуют**, поэтому скелетоны продолжают пульсировать при
`prefers-reduced-motion: reduce`.

**Фикс** — инвертировать логику: глобально гасить всё, точечно разрешать осмысленное
(спиннер «идёт загрузка» — это информация, его оставляем):

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
  /* Спиннеры — единственное исключение: вращение здесь несёт смысл «ещё грузится». */
  .animate-spin, .lx-anim-spin { animation-duration: 1s !important; animation-iteration-count: infinite !important; }
}
```

Это удаляет ~50 строк ручного списка и закрывает протечку навсегда.

### 5.3 [P2] Дубликат keyframes `lx-fade-in`

`src/styles.css:1497` и `src/styles.css:1896` — два разных определения одного имени.
Побеждает второе, первое мертво. Проверить, на какое из поведений рассчитывали

### 5.4 [P2] 24 icon-only кнопки без `aria-label`

**Поправка.** В первой редакции стояло «116 из 408». Это результат грубого подсчёта,
который засчитывал любую кнопку с `title=` и без `aria-label`, включая кнопки
с текстом внутри — у них доступное имя берётся из содержимого, и всё в порядке.

Реально проблемных (icon-only, содержимое — только `<svg>`) — **24**:
`EditorPanel` (5), `FilesPanel` (3), `HtmlPreviewPanel` (3), `TrayMenu` (2),
`BrowserPanel` (2), `RightPanel` (2), и по одной в `DevToolsPanel`, `EmptyDock`,
`HttpPanel`, `SearchPanel`, `TasksPanel`, `AppErrorBoundary`, `StatusBar`.

**Фикс:** пройти по icon-only кнопкам, добавить `aria-label` (значение совпадает с `title`).
Добавить ESLint-правило `jsx-a11y` на `<button>` без доступного имени, чтобы не отъезжало.

### 5.5 [P2] Анимации только «на вход», нет системы

Сейчас анимации — набор одноразовых CSS-классов (`.lx-anim-modal`, `.lx-anim-toast`, …),
навешиваемых вручную. Чего не хватает:

- **Exit-анимации** есть лишь у 4 сущностей (`lx-modal-exit`, `lx-palette-exit`,
  `lx-dialog-exit`, `lx-toast-out`); всё остальное — панели, дропдауны, виджеты
  правой панели — исчезает мгновенно. Появление плавное, исчезновение рывком.
- **Нет анимации переупорядочивания списков** — драг табов/виджетов, сортировка
  файлов, реордер проектов происходят скачком.
- **Нет общего примитива** — каждый оверлей сам помнит, какой класс навесить и когда
  снять; отсюда и разъезжающийся reduced-motion (5.2).

**Фикс (по возрастанию цены):**

1. Хук `useEnterExit(open, { enter, exit, duration })` — держит узел в DOM на время
   exit-анимации и возвращает нужный класс. Один примитив вместо ручных классов.
2. Прогнать через него дропдауны (`HtmlPreviewPanel` interval-picker, `TopBar`,
   `RightPanel`), виджеты правой панели и side-панели — дать им exit.
3. Для реордера — `View Transitions API`. WebView2 (Windows — основная платформа) и
   WKWebView его поддерживают; для Linux WebKitGTK нужен фолбэк «без анимации»,
   что естественно ложится на `document.startViewTransition?.()`.
4. ~~Микро-отклик `:active`~~ — **уже реализован**: `styles.css` содержит
   `button:not(.xterm *):not(.cm-editor *):not([disabled]):active { transform: scale(0.97) }`
   плюс `.lx-hover-lift` и подъём таба на hover. Пункт снят как ошибочный.
   А вот заготовка под ripple (`@keyframes lx-ripple` + `.lx-ripple`) действительно
   **не подключена** — не встречается ни в одном `.tsx`. Удалить как мёртвый CSS.

Всё новое обязано наследовать `--lx-dur*` и `--lx-ease*`, а не хардкодить `200ms`.

### 5.6 [P2] Нет шкалы отступов

Радиусы, длительности, цвета — токенизированы; отступы задаются Tailwind-числами
ad hoc. Для консистентного вертикального ритма между 27 панелями стоит зафиксировать
шкалу (4/8/12/16/24) и, что важнее, договориться о плотности: «панельная» плотность
(компактная) vs «модальная» (просторная).

## 8. Чего трогать не надо

Чтобы рефакторинг не сломал уже правильные решения:

- **PathGuard** и то, что read-only команды не ограничены — так задумано (нужно
  просматривать диск, чтобы открыть проект). Модель угроз описана в `pathguard.rs:1-14`.
- **`resolvePreviewSrc` → null** — осознанное сужение `assetProtocol.scope`; удалять
  надо мёртвый код вокруг, а не возвращать asset-протокол.
- **iframe без `allow-same-origin`** — это то, что не даёт превью читать локальные файлы.
- **`createUpdaterArtifacts: false` + `updater.active: false`** с комментарием про
  ключи подписи — не включать, пока нет ключей в CI secrets.
- **Отключение F5 / Ctrl+R** (`App.tsx:460`) — в десктоп-приложении перезагрузка убивает
  терминалы и layout. Это фича.
- **Freeze-detector** и `startupTelemetrySent`-латч — оба с подробным обоснованием,
  оба нужны.
