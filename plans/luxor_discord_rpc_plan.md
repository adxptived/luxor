## Часть 1. Расширенные идеи для сбора статистики

Чем больше уникального контекста мы соберём, тем полезнее будут дашборды и статусы в Discord.

### 🤖 1.1. Продвинутый трекинг AI-помощников (Claude Code, Cursor, Copilot, Aider)
- **Active Window Focus:** трекаем не просто запущенный процесс, а находится ли окно AI в фокусе. Свёрнутый Cursor не засчитывает время.
- **Индекс «AI-зависимости»:** соотношение времени ручного кодинга в IDE vs времени в чате с AI.
- **AI-спринты:** авто-детект сессий плотной работы с ИИ («Интенсивная 40-минутная сессия рефакторинга с Claude Code»).
- **Подсчёт сессий:** одна или несколько сессий за день считаются как общее наработанное время (с округлением до часов при необходимости). Если процесс не появлялся > 30 минут — сессия считается закрытой.
- **Потребление токенов / API** (если Luxor сам ходит в LLM): кол-во токенов и примерная стоимость в $.

### 🌿 1.2. Deep Git Analytics
- **Commit Impact Score:** «вес» изменений (churn rate: добавлено vs удалено строк), а не просто кол-во коммитов.
- **Git Flow State:** определение этапа работы по имени ветки (`bugfix/` → «Исправляет баги», `feature/` → «Пилит фичи»).
- **Измененные файлы:** кол-во `modified` / `added` / `deleted` (эквивалент `git status -s | wc -l`) — в проекте и в целом.
- **Conflict Resolution Time:** время в состоянии `MERGING` (детект по наличию `.git/MERGE_HEAD`).
- **Языки программирования:** анализ расширений файлов (Rust — 40%, TS — 60%).

### 🛡️ 1.3. Метрики аудита Luxor (киллер-фича)
- **Threat Neutralized:** сколько уязвимостей (High/Critical) устранено по подсказкам Luxor за неделю.
- **Скорость закрытия техдолга:** график уменьшения предупреждений (Warnings) во времени.
- **Проведено аудитов:** счётчик запусков проверок.
- **Cost Saved:** мотивационная метрика («Сэкономлено $15,000 на услугах секьюрити-аудиторов»).

### 🧘 1.4. Здоровье и продуктивность
- **AFK / Idle Detection:** трекинг инпутов мыши/клавиатуры на уровне ОС (без кейлоггера). 5 минут простоя → пауза сессии + статус ☕ AFK.
- **Burnout Alert:** сессия > 4 часов без перерыва → событие «предложить сделать перерыв».
- **Ночной кодинг:** трекинг работы после полуночи.

### 🎮 1.5. Геймификация
- **Streaks:** сколько дней подряд пользователь кодит.
- **Ачивки:** «Симбиот» (100 ч с ИИ), «Хранитель чистоты» (исправлено 50 багов), «Ночной дозор» (10 ч после полуночи).

## Часть 2. Архитектура бэкенда (Rust)

Система сбора должна быть асинхронной, независимой и не тормозить UI.

### 2.1. `TelemetryEngine` (сборщик)
- Работает через `tokio::spawn` в фоне.
- Определяет состояние: `Active`, `Idle`, `Focus` (окно свёрнуто).
- Опрашивает источники: `sysinfo` (процессы), `git2` (репозиторий), внутренние счётчики приложения.

### 2.2. Хранилище — SQLite (WAL)
- Лёгкая локальная БД через `rusqlite` / `sqlx`.
- Включаем `PRAGMA journal_mode=WAL;` → фронтенд читает одновременно с записью фоновым потоком без блокировок.
- Хранение всех timestamp в **UTC**.

### 2.3. Шина сообщений (Channels)
- `tokio::sync::broadcast` / `mpsc` → свежие данные летят сразу в два места:
  - модуль **Discord RPC** (обновление статуса);
  - **Tauri Window** через `app.emit_all` (живое обновление графиков).

### 2.4. Event-Driven вместо тупого Polling'а
- Крейт `notify` слушает события ОС об изменении файлов в `.git/`. Изменение → обновление Git-статистики. Нагрузка на CPU ≈ 0%.

## Часть 4. Интеграция Discord RPC

Ограничения UI Discord: 1 большая картинка, 1 маленькая, 2 строки текста (Details/State) по 128 символов, до 2 кнопок.

### 4.1. Стратегия «Карусель статусов» (ротация раз в 10–15 сек)
- **Кадр 1 (Проект):**
  - `large_image`: логотип языка (Rust)
  - Details: `🛠️ Проект: luxor-backend`
  - State: `🌿 Ветка: main`
- **Кадр 2 (Сотрудничество с ИИ):**
  - `large_image`: логотип Claude/Cursor · `small_image`: лого Luxor
  - Details: `🤖 Pair-programming с Claude`
  - State: `⏱️ Сессия: 2ч 10м`
- **Кадр 3 (Аудит):**
  - `large_image`: щит (зелёный/красный по числу багов)
  - Details: `🛡️ Просканировано 12k строк`
  - State: `🐞 2 проблемы`

### 4.2. Priority Status Queue
1. **Priority 1 (критические, 15с):** «🎉 Нашёл 0-day уязвимость!» — перебивает всё.
2. **Priority 2 (action, 30с):** «🧑‍💻 Пишет код в `src/main.rs`».
3. **Priority 3 (background, 15с):** «🤖 Claude Code: активен 2 часа».

### 4.3. Динамические ассеты
- В Dev Portal грузим пачку картинок: языки (`lang_rust`, `lang_ts`), агенты (`ai_claude`, `ai_cursor`), статусы аудита (`audit_ok`, `audit_warn`).
- Rust подставляет `large_image_key` динамически по текущему открытому файлу.

### 4.4. Кнопки (Rich Presence Buttons)
- Кнопка 1: «⬇️ Скачать Luxor» (репозиторий/сайт).
- Кнопка 2: «💬 Discord комьюнити».

## Часть 5. Приватность и настройки

Новая страница настроек **«Интеграции и Данные» (Integrations & Privacy)**.

### 5.1. Режимы
- **Paranoid / Ghost Mode:** одной кнопкой отключается весь сбор + RPC. В БД только локальный timestamp старта.

### 5.2. Детальные настройки Discord RPC
- `[Toggle]` Включить Discord Rich Presence.
- `[Checkbox]` Что показывать: `Название проекта` · `Ветку Git` · `Статус AI` · `Результаты аудита`.
- `[Slider]` Скорость смены статусов (5–30 сек).
- `[Toggle]` Скрывать приватные названия (папки → «Секретный проект»).

### 5.3. Smart Masking (умное скрытие)
- В Discord улетает `Работает над: 🔒 Private Project`.
- Файлы отображаются как `Редактирует: *.rs файл` вместо `src/auth_keys.rs`.

### 5.4. Regex Blacklist
- Пользователь добавляет пути/слова (`*work*`, `*nda*`). Совпадение в имени ветки/папки → RPC автоматически отключается для этой папки.

### 5.5. Настройки сбора статистики (без привязки к Discord)
- `[Toggle]` Включить локальный сбор телеметрии (выключение полностью останавливает фоновый парсинг).

### 5.6. Управление данными (Data Management)
- Экспорт в CSV / JSON.
- «Удалить всю историю» (очистка SQLite).
- **Local-First Guarantee:** плашка «Вся статистика хранится локально в `local_stats.db` и НИКОГДА не отправляется на наши серверы».

## Часть 7. Детальная модель данных (SQLite)

### 7.1. Структура таблиц
```sql
-- Атомарные интервалы активности (сырые данные)
CREATE TABLE activity_intervals (
    id            INTEGER PRIMARY KEY,
    start_utc     INTEGER NOT NULL,   -- Unix ms, всегда UTC
    end_utc       INTEGER NOT NULL,
    category      TEXT NOT NULL,      -- 'coding' | 'ai' | 'audit' | 'idle'
    project_id    INTEGER,
    agent_id      INTEGER,            -- какой AI был активен (nullable)
    branch        TEXT,
    is_focused    INTEGER DEFAULT 1   -- было ли окно в фокусе
);

-- Справочник проектов (для маскинга и дедупликации)
CREATE TABLE projects (
    id            INTEGER PRIMARY KEY,
    path_hash     TEXT UNIQUE,        -- SHA256 пути (если включен маскинг)
    display_name  TEXT,
    is_masked     INTEGER DEFAULT 0,
    primary_lang  TEXT,
    color         TEXT
);

-- AI агенты
CREATE TABLE ai_agents (
    id            INTEGER PRIMARY KEY,
    name          TEXT,               -- 'Claude Code', 'Cursor', 'Copilot'
    process_match TEXT,               -- паттерн процесса
    icon_key      TEXT                -- ключ ассета в Discord
);

-- Дневные агрегаты (денормализация для быстрых дашбордов)
CREATE TABLE daily_rollups (
    date           TEXT PRIMARY KEY,  -- YYYY-MM-DD (локальная дата)
    total_seconds  INTEGER,
    ai_seconds     INTEGER,
    coding_seconds INTEGER,
    commits        INTEGER,
    lines_added    INTEGER,
    lines_removed  INTEGER,
    audits_run     INTEGER,
    issues_fixed   INTEGER
);

-- Git события
CREATE TABLE git_events (
    id            INTEGER PRIMARY KEY,
    ts_utc        INTEGER,
    project_id    INTEGER,
    event_type    TEXT,               -- 'commit' | 'branch_switch' | 'merge'
    lines_added   INTEGER,
    lines_removed INTEGER,
    branch        TEXT
);

-- Прогресс ачивок
CREATE TABLE achievements (
    key           TEXT PRIMARY KEY,
    progress      REAL,               -- 0.0 → 1.0
    unlocked_at   INTEGER             -- nullable
);
```

### 7.2. Индексы и оптимизация
- `CREATE INDEX idx_intervals_time ON activity_intervals(start_utc, end_utc);`
- Материализация `daily_rollups` фоновой задачей в полночь (локальное время) + инкрементальное обновление текущего дня каждые 5 минут.
- **Retention:** сырые `activity_intervals` старше 90 дней схлопываются в `daily_rollups` и удаляются → база компактна (десятки МБ за годы).

## Часть 8. Протокол Discord RPC (технические детали)

### 8.1. Транспорт и подключение
- Discord IPC через локальный сокет: Unix Domain Socket (`/tmp/discord-ipc-0..9`) на macOS/Linux, Named Pipe (`\\.\pipe\discord-ipc-0`) на Windows.
- Перебор сокетов **0–9** (несколько клиентов: Stable / Canary / PTB).
- **Reconnect Loop:** экспоненциальный backoff (1с → 2с → 4с → … → max 60с).

### 8.2. Структура Activity Payload
```jsonc
{
  "details": "🛠️ luxor-backend · main",       // строка 1 (макс 128 символов)
  "state": "🤖 Claude Code · 2ч 10м",          // строка 2 (макс 128 символов)
  "timestamps": { "start": 1718900000 },         // нативный таймер "elapsed"
  "assets": {
    "large_image": "lang_rust",                  // ключ из Dev Portal
    "large_text": "Rust · 64% проекта",          // тултип при наведении
    "small_image": "ai_claude",
    "small_text": "Claude Code активен"
  },
  "buttons": [
    { "label": "⬇️ Скачать Luxor", "url": "https://..." },
    { "label": "💬 Discord комьюнити", "url": "https://..." }
  ]
}
```

### 8.3. Тонкости и ограничения
- **Rate Limit:** обновления не чаще 1 раза в 15 сек → debounce, шлём только последний актуальный кадр.
- **Эмодзи:** только Unicode (не кастомные); подобрать набор, корректный на всех ОС.
- **Кнопки:** URL обязан быть `https://`.
- **Анти-мерцание:** не отправлять payload, если хэш состояния не изменился (`DefaultHasher`).

## Часть 9. Кросс-платформенный трекинг (Edge Cases)

### 9.1. Детектирование AI-агентов по ОС
| Агент       | Windows                    | macOS                       | Linux                     |
|-------------|----------------------------|-----------------------------|---------------------------|
| Claude Code | `claude.exe`, node-обёртка | `claude`, процесс терминала | `claude` (в shell)        |
| Cursor      | `Cursor.exe`               | `Cursor.app`                | `cursor` / AppImage       |
| Copilot     | дочерний процесс IDE       | language-server процесс     | `copilot-language-server` |
| Aider       | `python ... aider`         | `aider`                     | `aider`                   |

- **Проблема CLI-агентов (Claude Code, Aider):** нет окна → детект по **командной строке процесса** (`sysinfo` → `cmd()`) + по изменениям файлов (notify).
- **Абстракция:** trait `ProcessProvider` с реализациями `WindowsProvider`, `MacProvider`, `LinuxProvider`.

### 9.2. Фокус активного окна
- Windows: `GetForegroundWindow` + `GetWindowThreadProcessId`.
- macOS: `NSWorkspace.frontmostApplication` (требует Accessibility-разрешений → онбординг с просьбой выдать права).
- Linux: X11 (`_NET_ACTIVE_WINDOW`) vs Wayland (часто закрыт → fallback на процессы/CPU).

### 9.3. Системные события питания
- Подписка на sleep/wake/lock.
- `Sleep`/`Lock` → принудительно закрыть открытый интервал (иначе ночёвка ПК = «18 часов кодинга»).
- `Wake` → новая сессия.

## Часть 10. Бюджеты производительности

| Ресурс           | Лимит (Idle)    | Лимит (Active)                      |
|------------------|-----------------|-------------------------------------|
| CPU (фон. поток) | < 0.1%          | < 1%                                |
| RAM (телеметрия) | < 15 MB         | < 30 MB                             |
| Запись на диск   | 1 flush / 5 мин | батчинг, без fsync на каждое событие|
| Размер БД        | < 50 MB за год  | авто-retention                      |

- **Адаптивный поллинг:** окно не в фокусе + нет активности → реже опрос (60с → 5мин).
- **Lazy init:** Discord RPC и тяжёлые модули грузятся только если функция включена.
- **Battery-aware:** на батарее — частота ниже в 2–3 раза (`battery` crate).

## Часть 11. Аналитический слой (Insights Engine)

### 11.1. Еженедельные авто-отчёты (Weekly Digest)
- Каждый понедельник: «На прошлой неделе: 28ч работы (↑15%), пик — вторник 10:00–13:00, 64% коммитов в паре с Claude».

### 11.2. Паттерны и эвристики (на правилах)
- **Прайм-тайм:** часы наибольшей продуктивности.
- **Корреляция AI ↔ скорость:** «В дни активного Claude закрываешь на 30% больше задач».
- **Деградация безопасности:** алерт при росте Critical-уязвимостей.

### 11.3. Опционально: локальный ML-инсайт
- Лёгкая модель / линейная регрессия: «Техдолг закроется за ~12 дней».
- Кластеризация типов сессий («дни рефакторинга» vs «дни фич»).

## Часть 13. Расширяемость (Plugin / Extensibility)

### 13.1. Trait-based провайдеры
```rust
trait MetricProvider {
    fn name(&self) -> &str;
    fn collect(&self, ctx: &CollectorContext) -> Vec<MetricEvent>;
    fn poll_interval(&self) -> Duration;
}
```
- Новая метрика (новый AI-агент, Docker, время в браузере) = новый провайдер без изменения движка.

### 13.2. Будущие интеграции (бэклог)
- **Webhook-уведомления:** ачивка / завершение аудита → Slack/Telegram/Discord-вебхук.
- **Командный режим (Team Stats):** opt-in синхронизация агрегатов команды — лидерборды.
- **CLI-компаньон:** `luxor stats today`.
- **IDE-плагины:** тонкие расширения VS Code / JetBrains, шлющие события в локальный сокет.

## Часть 14. Стратегия тестирования

### 14.1. Уровни тестов
- **Unit (Rust):** агрегация интервалов, склейка сессий, дебаунс RPC, маскинг.
- **Integration:** мок Discord IPC-сокета → корректность payload и reconnect.
- **E2E (Playwright — уже есть):** дашборд, тумблеры приватности, проверка что выключенный RPC реально не шлёт данные.
- **Property-based (`proptest`):** случайные последовательности (sleep, focus, idle) → сумма времени никогда не превышает реально прошедшее («защита от 25 часов в сутках»).

### 14.2. Симулятор времени
- Trait `Clock` вместо прямых `Instant::now()` → `MockClock` для тестов полуночи, таймзон, DST.

### 14.3. Чек-лист граничных сценариев
- [ ] ПК ушёл в сон на 8ч → сессия закрыта корректно.
- [ ] Смена таймзоны (перелёт) → графики не ломаются (UTC + конверсия на фронте).
- [ ] DST (зима/лето) → нет дубля/пропуска часа.
- [ ] Discord закрыт → нет паники, тихий reconnect.
- [ ] 2 клиента Discord → подключаемся к первому доступному сокету.
- [ ] Monorepo 5 ГБ → Git-сборщик не вешает систему (notify вместо обхода дерева).
- [ ] Нет интернета → работает локально, копит данные.
- [ ] Повреждённая БД → авто-восстановление из WAL / новая БД с бэкапом старой.

## Часть 15. Безопасность и надёжность

- **Защита от утечки:** пути проектов хешируются (SHA256) при маскинге; реальные имена не покидают локальную БД.
- **Конфиг-файл:** настройки приватности в `config.toml` (человекочитаемый, без секретов).
- **Atomic writes:** запись конфига и flush БД через временный файл + atomic rename.
- **Graceful shutdown:** на закрытие / SIGTERM → финальный flush + корректное закрытие RPC (иначе в Discord «зависнет» старый статус).
- **Версионирование схемы БД:** таблица `schema_version` + миграции при обновлении (никогда не терять данные).
